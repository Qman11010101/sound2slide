# 48 レーン拡張フィールドのはみ出し規則

Margrete の「フィールド拡張を有効にする (48 レーンを使用)」で作る譜面について、
どこまでノーツを中央 16 レーンの外に出してよいかを実測でまとめたものです。
sound2slide を 48 レーンに対応させるときの仕様として使います。

- 検証環境: Margrete v1.9.3（2026-10-31 時点の配布最新版）を Linux + Wine 上で実行
- 検証方法: [`tools/mgprobe`](../tools/mgprobe) でノーツを配置し、譜面出力が通るかどうかを見た
- UMIGURI 本体でのプレイ感は確認していません。ここに書いた規則はすべて Margrete の出力チェックの挙動です

## 座標

| 範囲 | x |
|---|---|
| 左の拡張 16 レーン（叩けない） | -16 〜 -1 |
| 中央 16 レーン（叩ける） | 0 〜 15 |
| 右の拡張 16 レーン（叩けない） | 16 〜 31 |

ノーツは `x` から `x + width - 1` までのレーンを占めます。
「中央に掛かる」とは、占めるレーンのうち 1 つでも 0 〜 15 に入っていることを指します。

`.ugc` では x を `x + 16` として 1 文字（`0-9A-Za-z` の 62 進）で書き出します。
ヘッダーには `@FLAG EXFIELD TRUE` が入ります。

## どこで弾かれるか

- 違反があると**譜面出力（F5）が止まり**、「UMIGURI Chart 規格に違反したノーツが見つかりました」と表示されます。
  違反ノーツは校閲ウィンドウに「ノーツがプレイ可能な領域から完全にはみ出しています」として並びます。
- 校閲（ツール > 校閲）の「プレイ不可なフィールド外ノーツ」は既定でオフですが、譜面出力では常に検査されます。
- スライドの違反は、どこがはみ出していても始点（SLIDE BGN）の位置で報告されます。

## スライド以外のノーツ

| ノーツ | 完全に外 | 一部だけ中央に掛かる |
|---|---|---|
| TAP / EXTAP / FLICK | NG | OK（1 レーンでよい） |
| HOLD | NG | OK |
| 外の TAP に AIR を載せたもの | NG（TAP が違反） | — |
| DAMAGE | OK | OK |
| AIR-CRUSH | OK | OK |

## スライド

### 規則

1. **始点は中央に掛かっていなければならない。** 始点が外で直後（10 tick 後）に中へ入る形も NG。
2. **中継点（STEP / CONTROL）は外にあってよい。** 判定されるのは、時間ごとの「中央に掛かっているか」だけ。
3. **中央から完全に外れている区間の長さ**を、次の上限と比べる。

   | 外れている区間の位置 | 上限 |
   |---|---|
   | 途中（あとで中央に戻る） | 約 **100 ms** |
   | 終点まで外のまま終わる・終点に AIR なし | 約 **50 ms** |
   | 終点まで外のまま終わる・終点に AIR あり | 約 **300 ms** |

4. 上限は **tick ではなく実時間（ms）**。BPM が区間の途中で変わる場合も実時間で数える。
   スクロール速度のイベント（TIL / ノーツ速度変化）は関係しない。
   tick と時間の関係は下の「tick の長さ」を参照。
5. 外れている区間は**区間ごとに独立**して判定される。外 90 tick → 中 2 tick → 外 90 tick（BPM 120）は OK。
6. 中継点の間の位置は、**左端と右端をそれぞれ線形補間してから四捨五入**し、その整数レーンで判定する。
   x と幅を別々に丸めるのではない。例えば中央から x = -4（幅 4）へ直線で動くと、右端が 0.5 を下回った時点で外扱いになる。
7. 終点の AIR は向き（上・下・斜め）を問わない。AIR-HOLD / AIR-SLIDE を付けても上限は AIR と同じ 300 ms。
   なお Margrete の UI でスライド終点に AIR-HOLD / AIR-SLIDE を置くと、終点 → AIR → AIR-HOLD（AIR-SLIDE）始点 → 終点、の入れ子になる。
8. 左右で同じ値。

### tick の長さ

Margrete の tick は**拍子に関係なく 4 分音符 = 480 tick**で、BPM も 4 分音符基準です。

- 1 tick = 60000 / (BPM × 480) ms（BPM 120 で ≒ 1.042 ms、BPM 240 で ≒ 0.521 ms）
- 1 小節 = 1920 × 分子 / 分母 tick（4/4 は 1920、3/4 は 1440、3/8 は 720、7/8 は 1680）

3/4・3/8・7/8 のいずれでも、4/4 と同じ tick 数で OK / NG が切り替わりました（下の測定値）。
校閲ウィンドウの位置表示も、3/4 では tick 3840 を「3'960」（1 小節 1440 tick）と表示しました。

> **注意**: 現在の sound2slide は「1 小節は拍子によらず 1920 tick」とみなし、拍子に応じて時間をスケールしています
> （`timing.rs` の `elapsed_seconds`、`generate.rs` の `ticks_per_second`。例えば 3/4・BPM 120 で 1280 tick/秒）。
> 上の結果からは Margrete では拍子によらず 960 tick/秒になるはずで、4/4 以外の譜面では時間計算や
> 拍子イベントの小節番号（`tick / 1920`）がずれている可能性があります。4/4 以外の譜面で一度確認してください。

### 測定値

外れている時間は「外にある tick の数 × 1 tick の長さ」で計算しています。

| 状況 | OK だった最大 | NG だった最小 |
|---|---|---|
| 途中・BPM 120 | 95 tick = 99.0 ms | 97 tick = 101.0 ms |
| 途中・BPM 240 | 191 tick = 99.5 ms | 193 tick = 100.5 ms |
| 途中・区間中央で BPM 120→360 / 360→120 | 141 tick ≒ 98 ms | 151 tick ≒ 105 ms |
| 終点まで・AIR なし・BPM 120 | 46 tick = 47.9 ms | 51 tick = 53.1 ms |
| 終点まで・AIR なし・BPM 240 | 91 tick = 47.4 ms | 101 tick = 52.6 ms |
| 終点まで・AIR あり・BPM 120 | 241 tick = 251 ms | 361 tick = 376 ms |
| 終点まで・AIR あり・BPM 240 | 571 tick = 297.4 ms | 581 tick = 302.6 ms |
| 途中・BPM 120・3/4、3/8、7/8 | 95 tick = 99.0 ms | 97 tick = 101.0 ms |
| 終点まで・AIR なし・BPM 120・3/4、3/8、7/8 | 46 tick = 47.9 ms | 51 tick = 53.1 ms |

丸めの確認に使ったケース（いずれも BPM 120・終点に AIR なし。外れている時間は丸めを入れた計算値）:

| 形 | 計算上の外れている時間 | 結果 |
|---|---|---|
| x 0→-4、幅 4、360 tick | 45 tick = 46.9 ms | OK |
| x 0→-4、幅 4、400 tick | 50 tick = 52.1 ms | NG |
| x -4 固定、幅 5→3、60 tick | 45 tick = 46.9 ms | OK |
| x -4 固定、幅 5→3、80 tick | 60 tick = 62.5 ms | NG |
| x -2→-4、幅 3→4、80 tick（右端 1→0） | 40 tick = 41.7 ms | OK |
| x -2→-4、幅 3→4、120 tick（右端 1→0） | 60 tick = 62.5 ms | NG |

最後の 2 行は、x と幅を別々に丸める方式なら 120 tick でも外が 30 tick（31 ms）で OK になるはずのケースです。
NG になったので、端を丸める方式と判断しました。丸めを入れず連続的に判定する方式なら、どの行も終点の一瞬だけが外になるため、すべて OK になるはずです。

## 48 レーンの外（x < -16 や x + width > 32）

**出力チェックを通ってしまうが、`.ugc` の x が壊れる**ので、絶対に出さないこと。

- DAMAGE x = -24、AIR-CRUSH x = -30、スライドが 90 tick だけ x = -24 へ出る形、はいずれも出力に成功した。
- しかし `.ugc` では、これらの x がすべて `z`（= 61、つまり x = 45）として書かれていた。
  左の外に置いたつもりのノーツが、右の遠くに置かれたものとして読まれる。Margrete 側の不具合とみられる。
- 右側の x = 40 は `u`（= 56）と正しく書かれていた。x ≦ 45 までは書けるが、48 レーンの外であることに変わりはない。

## sound2slide への組み込み方針

### 検査

生成したスライドごとに、次の検査を行う。

```rust
/// 補間した左端・右端が中央 16 レーンに掛かっているか。
/// Margrete は四捨五入した端で判定する。ちょうど .5 の扱いは未確認なので外側に倒す。
fn covers_center(left: f64, right: f64) -> bool {
    right > 0.5 && left < 15.5
}
```

1. すべての点で `-16 <= x` かつ `x + width <= 32`（48 レーンの外に出さない）。AIR-CRUSH（rainbone 出力）にも適用する。
2. 始点の tick で `covers_center` が真。
3. 始点から終点まで 1 tick ずつ、前後の点から `left = x`、`right = x + width` を線形補間して `covers_center` を調べ、偽が続く区間 `[a, b]` を集める。
4. 区間の長さを `ms(a, b + 1)` とする。`ms` は BPM の変化を考慮して tick を実時間に直す関数
   （BPM が一定の区間ごとに `60000 / (bpm * 480)` ms/tick を足し合わせる。拍子は関係しない）。
5. `b` が終点の tick なら上限は AIR なし 50 ms / AIR あり 300 ms、それ以外は 100 ms。
   境界ちょうどの扱い（未満か以下か）は未確認なので、**90 / 40 / 280 ms** 程度の余裕を持たせる。

スライドは長くても数千 tick なので、1 tick ごとに調べても十分速い。
現在の sound2slide は生成開始位置の BPM を 1 つだけ使って時間を計算しているので、
スライドの途中で BPM が変わる譜面に備えるなら、生成範囲内の BPM の変化点（`find_bpm_event`）を拾う必要がある。

### 違反したときの直し方（案）

- 始点が外: 始点の x を中央側に寄せる（`right >= 1` かつ `left <= 15` になるまで）。
- 途中の区間が長すぎる: 区間内の点を中央側に寄せて、外れている時間を上限内に分割する。
  外れている区間は独立に判定されるので、ごく短く（1 tick 以上）中央に戻せば分割できる。ただし、見た目やプレイ感とのバランスは UMIGURI で確認が必要。
- 終点まで外のまま終わる区間が長すぎる: 終点に AIR を付けて上限を 300 ms にする（出力設定で選ばせる）か、終点付近を中央側に寄せる。
- そもそも外に出したくない場合は、生成時に振れ幅を中央 16 レーンに収める（現在の挙動）。

## その他の発見

- Margrete はプラグインの `.ini` を UTF-8 として読まない。Wine（日本語ロケール）上では、BOM なし UTF-8 の
  日本語が文字化けし、改行の解釈も崩れて `dev=...` が説明欄に混ざった。公式サンプルの `.ini` は BOM 付き UTF-16LE。
  sound2slide.ini も BOM なし UTF-8 なので、Windows 実機で表示が崩れていないか確認するとよい。
- Margrete の UI でスライド終点に AIR-HOLD / AIR-SLIDE を置くと、自動で上向き AIR が挟まる（規則 7）。
  AIR の向きは `direction` の値で 2 = 上、3 = 下、7 = 左上、8 = 右上、9 = 左下、10 = 右下。

## まだ確認していないこと

- 境界ちょうど（100 / 50 / 300 ms ちょうど、端がちょうど .5）の扱い。
- タイムラインが複数ある譜面（`timeline_id` が 0 以外のノーツ）。
- 曲線制御点（CURVE_CONTROL）を使ったスライド。譜面出力時に通常の制御点へ変換されるとのことだが未検証（sound2slide は使っていない）。
- UMIGURI 本体でのプレイ感・判定。
- Margrete v1.9.3 より新しい版。
