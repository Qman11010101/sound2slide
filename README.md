# sound2slide

音声波形からスライドを生成する、Windows x64向けMargreteプラグインです。

画面の表示言語は日本語・英語・繁体字中国語・韓国語から、左側パネル上部（タイトルの右）の言語メニューで切り替えられます。
選択した言語は保存されず、起動時は常に日本語で表示します。

## インストール

GitHub ReleasesからZIPをダウンロードして展開してください。
`sound2slide.dll` と `sound2slide.ini` をMargreteのプラグイン配置先に置き、
`third-party-library.txt` はライセンス通知として保管してください。

## フィールド

「フィールド」で「通常16レーン」「拡張48レーン」を選択できます。
起動時と参照する譜面の選択時に、取得できた譜面の情報からどちらかを選びます。
手動でフィールドを選択した後は、画面を閉じるまでその選択を維持します。
拡張48レーンでは、通常の16レーンの左右に16レーンずつ追加した範囲で波形を生成します。
普通の波形とレインボーンの移動範囲は最大48レーン、各ノーツの幅と左右対称の波形の最大幅は従来どおり16レーンです。
中央の位置は通常モードと共通です。プレビューでは通常範囲の左右の境界線を強調します。
通常のスライド・レインボーンともに、始点・終点・中継点・制御点を選択したフィールド内へ制限します。
拡張48レーンでは必ず `-16 <= x` かつ `x + 幅 <= 32` に収めます。
書き込み直前にも範囲を検査し、範囲外のノーツがあれば譜面全体への追加を中止します。

Margreteで編集中の譜面の親ノーツ・子ノーツ・制御点に通常範囲外の配置があれば拡張48レーンを選びます。
それ以外は、選択した保存済みの `.mgxc` ファイルの拡張フィールド設定を参照します。
音声と同じフォルダーの譜面が1件なら自動で選択し、複数なら「判定元の譜面」で選択できます。
音声のオフセット計算で譜面を選択した場合も、そのファイルを判定元にします。
保存済みの設定には未保存の変更は反映されません。
判定元がない場合や設定を読み取れない場合は、通常16レーンを選びます。
必要に応じて手動で切り替えてください。

この選択はsound2slideの生成範囲に適用されます。
Margrete側の拡張フィールド設定は変更しないため、拡張領域を使う場合は譜面情報でも有効にしてください。

### 48レーンの校閲

拡張48レーンでは、生成結果のはみ出しを自動で検査し、警告件数と詳細を表示します。
詳細にはスライド番号、譜面の絶対tick、理由、中央から外れている区間の時間を表示します。
検査中も操作でき、中央16レーンからのはみ出し警告があっても譜面へ追加できます。ノーツの自動補正は行いません。

通常のスライドは、始点が中央16レーンに掛かるか、途中や終端で中央から外れる時間が長すぎないかを検査します。
Margreteで実測した上限の目安は途中100 ms・終端50 msです。境界が未確定のため、余裕を持たせて90 ms・40 msから警告します。
sound2slideの出力には終点のAIRを付けないため、AIRありの300 msの上限は適用しません。
時間は編集中の譜面のBPM変更を考慮し、4分音符480 tickとして計算します。拍子やスクロール速度では変わりません。
BPMを取得できない場合は、校閲を完了できなかった旨を表示します。
レインボーンは中央からのはみ出しを許可します。48レーン全体の外へは配置しません。

警告が出た場合は、移動範囲を狭める、始点・終点を中央に寄せるなどして調整してください。
警告は[実測したはみ出し規則](docs/exfield-48lanes.md)に基づく目安です。Margreteの譜面出力でも確認してください。

## 中央線なしのスライド

出力が「スライド」のとき、「中央線を表示しない」を有効にすると、中央線のないスライドを生成します。
プレビューでも中央線を非表示にします。波形の配置や中継点の設定は変わりません。
レインボーンにはこの設定を適用しません。

## レインボーン

出力を「レインボーン」にすると、AIR-CRUSHのノーツを付けずに線だけを追加します。
線の色、高さ、描画軸を設定できます。「線の軸」はX軸、Y軸（左右）、Z軸（縦）から選択し、初期値はX軸です。
描画軸の指定にはMargrete v1.9.0以降と対応するUMIGURIが必要です。
軸の選択は線の描画に適用され、波形の配置経路や高さは変わりません。
プレビューは配置経路を表示し、軸による立体的な描画の違いは再現しません。

## 更新通知

sound2slideの画面を開くたびに、GitHub Releasesの最新版をバックグラウンドで確認します。
利用中のビルドより新しい正式リリースがある場合は、更新通知のダイアログを表示します。
ダイアログを閉じた後も、左下の「オープンソースライブラリ」ボタンの上に更新がある旨と配布ZIPのダウンロードリンクを表示します。
ダイアログの「リリースページを開く」または左下のリンクから配布ZIPをダウンロードし、Margreteを終了してからファイルを差し替えてください。
自動ダウンロードや自動更新は行いません。通信失敗時や更新がない場合、ダイアログは表示しません。
通信中に画面を閉じた場合は、確認処理の終了を待ってからMargreteへ戻ります。
更新判定にはビルド時のGitコミットを使用するため、Git情報のないソースから作成したビルドでは通知しません。

## ビルド

Rustのstableツールチェーン、Visual Studio 2022のC++ビルドツール、CMakeが必要です。
プロジェクトのルートで以下を実行してください。

```powershell
./scripts/test.ps1
./scripts/build.ps1
./scripts/package-release.ps1
```

`dist/sound2slide-windows-x64.zip` にDLL、INI、ライセンス通知を出力します。
ライセンス通知の生成時に、未導入なら `cargo-about` を自動インストールします。

marmkmtのC++ソース、Margrete Plugin SDK、marmkmt-rsのRustバインディングは
ソースツリーに同梱しています。サブモジュールの取得は不要です。
marmkmtは静的リンクされ、配布ZIPに別のライブラリDLLを追加する必要はありません。

## 開発

開発は `develop` で行い、PRで `main` にマージします。
Windows CIは整形、テスト、ビルド、ライセンス生成、ZIP作成を検証します。
`main` のCI成功後に、日本時間の `yyyy-mm-dd` をタグとするGitHub ReleaseへZIPを公開します。
同じ日の再リリースでは、同日のReleaseを1件のまま更新し、タグを `yyyy-mm-dd-2`、`yyyy-mm-dd-3` のように採番します。
ZIPとリリースノートを差し替え、以前のタグはソースの履歴として残します。
同じコミットのCI再試行では番号を増やしません。
